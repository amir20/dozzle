# Dozzle Cloud

[Dozzle Cloud](https://cloud.dozzle.dev) 是自托管 Dozzle 的可选托管伴侣。Dozzle 本身依然完全开源、完全自托管；Cloud 建在它之上，接手那些真正难以自己搭建的部分：判断什么值得把你叫醒，以及弄清楚到底是什么坏了。

你的 Dozzle 会向 Cloud 发起一条出站连接。没有入站端口，不需要公网 IP，也不用安装任何 agent。

**免费版让你耳根清净，Pro 会主动去找问题。**

## <Icon icon="mdi:bell-ring-outline" inline /> 免费版：一层智能通知

大多数日志告警不过是一条正则加一个 webhook，于是第一次崩溃重启循环就变成两百条一模一样的消息，最后你把整个频道静音了。免费版就是为了修好这一段，而且它是完整的告警产品，不是它的试用版。

- **智能告警** —— 你的 Dozzle 规则触发的每一条告警，都会被整理成一句话，说明原因、是哪个容器、有多严重，并附上跳回你自己 Dozzle 中那一行日志的链接。
- **重复会被折叠** —— 47 次崩溃汇成一条写着 47 的告警。恢复时还会收到一条恢复提醒。
- **默认安静** —— 每个渠道都支持抑制、按严重程度过滤和按模式静音。静音的是*这一类告警*而不是眼前这一条，真正不同的仍然会送达。
- **所有渠道** —— 邮件、Telegram、Discord、Slack、ntfy、webhook 和浏览器推送，免费版全都有。见[通知渠道](/zh/guide/dozzle-cloud/channels)。
- **搜索和指标都包含在内** —— 每个事件一到就能检索，CPU、内存、网络和磁盘都会作为历史记录下来。两者都不占用事件额度。
- **每周一条发现** —— 即使在免费版，Cloud 也会读你的日志，把没有任何告警发现的最严重问题挑出来。
- **开箱可用的默认规则** —— 连接实例时会自动为你创建一条（以错误码退出的容器），所以新账号第一天就能收到有用的告警，什么都不用配。
- **聊天 agent 和 MCP** —— 在 Telegram 或 Discord 里问“今天有报错吗？”，只要你在实例上开启了[操作](/zh/guide/actions)，还能在同一个会话里启动、停止或重启容器。MCP 访问在所有套餐中都是无限的。

> [!TIP]
> 新连接的实例会获得 7 天完整的 Pro 体验：每天早上推送全部发现。之后免费版会稳定在每周一条。

## <Icon icon="mdi:robot-outline" inline /> Pro：在任何告警之前就去找问题

免费版告诉你*出事了*，没事的时候则保持安静。Pro 是不等告警出现就动手的那一半。

- **每天早上主动巡检** —— Cloud 读你的错误日志，归纳成模式，报告哪些值得修。磁盘慢慢被写满、容器悄悄地重启循环，就是在这里、在一条告警都没触发的日子里被发现的。这不需要任何告警规则存在。
- **每条发现，每天，都带修复建议** —— 不是每周一条、其余锁住。发现会随着问题持续而逐日累积（“仍在发生，第四天，严重了三倍”），问题停止时自动关闭。
- **会主动去看的分诊** —— 当仅凭告警文本无法判断时，它会检查容器、读取前后日志再下结论，而不是靠猜。
- **随时发起完整调查** —— 一次点击就用更强的模型跑更多轮，跨你的容器、主机和时间线做关联，最后交给你根因和具体步骤。
- **所有主机，一个面板** —— 你运行多少个 Dozzle 实例就能连多少个。聊天里问的问题一次覆盖全部。
- **更长的记忆** —— 可检索的日志和指标从 24 小时变成 30 天，这是“昨晚发生了什么”和“这事是不是整个月都在发生”之间的差别。

完整对比见[套餐与限制](/zh/guide/dozzle-cloud/plans)。
